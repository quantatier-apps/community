# Contributing

You can help improve Quantatier's community resources by asking clear questions, sharing reproducible problems, correcting documentation, and contributing to discussions.

Use English for public contributions so readers can follow the same discussion.

## Choose where to contribute

| Area | Purpose | How to participate |
| --- | --- | --- |
| [Q&A](https://github.com/quantatier-apps/community/discussions/categories/q-a) | Product use, configuration, and workflow questions. | Create a question, answer one, or add relevant details. |
| [Issues](https://github.com/quantatier-apps/community/issues/new/choose) | Specific problems and proposed improvements. | Report a reproducible problem or explain a concrete use case. |
| [Announcements](https://github.com/quantatier-apps/community/discussions/categories/announcements) | Official user-facing updates, fixes, availability, and compatibility notes. | Maintainers publish posts; readers can comment and reply. |
| [Engineering](https://github.com/quantatier-apps/community/discussions/categories/engineering) | Maintainer-written series on quantitative system design, decisions, and experiments. | Read the series, ask questions, and discuss the work in comments. |

Technical implementation notes and internal refactoring details belong outside user-facing product announcements. Engineering articles are organized around an ongoing topic or question.

## Ask or answer a question

- Search for an existing discussion on the same subject.
- Describe your goal and what you have already tried.
- Include the product and version, with the relevant steps or error message.
- When answering, describe the conditions under which your suggestion worked.

The [Support](SUPPORT.md) guide includes a short template you can copy.

## Help reproduce a problem

Add your product version, operating system, and reproducible steps to the relevant issue. A small example and a clear expected result help distinguish the problem from differences in data or configuration.

Keep each report focused on one problem. Link related issues or discussions when useful.

## Suggest a documentation change

Open a pull request for a correction to the public documentation, or open an issue describing what needs fixing. Include the page link, the wording or example you suggest, and the reason for the change. If you first need help understanding the behavior, ask in [Q&A](https://github.com/quantatier-apps/community/discussions/categories/q-a).

Describe only behavior you have verified, including the product version or conditions that matter. Product availability and installation instructions should match the actual distribution.

## Documentation and product code

This repository maintains public product information, guides, and community feedback. Product source code is private and is not maintained here. Documentation contributions are welcome; report product defects through Issues so their handling can be followed.

When an answer resolves a reusable question, it can be added to the relevant guide and linked from the original discussion. Product announcements summarize user-visible changes; guides describe the current workflow.

## Keep contributions useful

Discuss specific behavior and explain the reasoning behind a suggestion. Distinguish observations, proposed changes, and open questions so readers can tell what has been confirmed.

Remove credentials, account details, private strategies, and restricted data before posting. Share examples you have permission to publish.
